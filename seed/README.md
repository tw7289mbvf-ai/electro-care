# Seed data

Generated by `scripts/build_seed.py` from `docs/referentiel_entretien_france.xlsx`. Never edit these files by hand: change the workbook (or `ENUMS` in the script), rerun `python scripts/build_seed.py`, commit both. The script fails if a task or an obligation points to an unknown equipment type.

| File | Content |
| --- | --- |
| `categories.json` | The user-facing categories: keys, French UI labels, display order, whether a maintenance plan exists |
| `equipment_types.json` | Equipment catalogue: legal status, lifespan, risk if neglected, nameplate help |
| `maintenance_tasks.json` | Task templates, linked to equipment by `equipment_type_id` |
| `legal_obligations.json` | French regulations: legal text, frequency, liable party, proof to keep, sanction, sources |
| `brand_nameplates.json` | Brand groups: identifiers to read, plate locations, validation patterns, source status |
| `enums.json` | Code contract: stable keys with French labels |
| `date_questions.json` | One date question per legal obligation, with its real legal interval and answer kind; `tasks` lists two ids for the shared appliance-and-flue questions; `tip` (column « Conseil si a confirmer ») is shown on an orange row, where to find the answer |
| `onboarding_questionnaire.json` | Questionnaire for first use and each new place: answers create equipment records; `skip_if` hides a question after a given answer; `unknown` marks « Je ne sais pas », which adds a to-check item; `follow_up.creates_if_yes` / `creates_if_no` are the types a yes/no follow-up creates (« Je ne sais pas » takes the no branch); `sets` fills a place field (Q01 → `property_type`); `rules` holds the cross-cutting rules |

## Key fields

- `category` is the display level shown to users (`categories.json`); `technical_group` only organizes the workbook. The equipment type, not the category, carries tasks and legal obligations.
- `categories[].maintenance_plan` is false when no equipment type belongs to the category (Électronique, Autre): warranty and documents still apply.
- `frequency.rule`: `every_n_months`; `season_anchor` (annual, scheduled in the months named in `season`); `threshold` (triggered by a measurement, described in `frequency.threshold`); `per_use`.
- `season_months`: months (1-12) when a task applies, parsed from `season`. For an annual task, when to schedule it; for a frequent one, its active window (pool tasks May to September). Empty = all year.
- `level`: maintenance level of a non-legal task, `essential` or `recommended`; `recommended` includes `essential`. Null for legal obligations, tracked at every level.
- `active_minutes`: hands-on time for the user, not the time an appliance runs; 0 when a professional does it. Level time estimates add `active_minutes / frequency.months` over the tasks scheduled at monthly frequency or less often.
- `frequency.months` can be fractional: 0.25 is weekly, 1.5 is every six weeks.
- `legal`: `yes`, `conditional` (depends on power, refrigerant charge, local rules or setup), `no`. Equipment types keep the original wording in `legal.note`.
- `nameplate.photo_target`: what to photograph. `dated_label` (gas hose, smoke detector) is enough on its own to create the reminder; `document` means a certificate or invoice replaces the plate.
- `legal_obligations[].risks`: what non-compliance costs, split for display (fine, insurance, liability, danger, other); null when not applicable.
- A task with `legal: "yes"` on an equipment type whose `legal.status` is `conditional` is shown "à confirmer" until the threshold is known (power, refrigerant charge).
- Smoke detectors: one equipment type per kind, `SEC-01` standalone, `SEC-08` linked to an alarm that isn't monitored, `SEC-09` linked to a monitored alarm. Date question kind `monitored` (T-157) is always up to date, labelled « Suivi par votre télésurveillance »; the provider's visits are recorded as interventions.
- `brand_nameplates[].patterns`: indicative regexes. Only entries with `status: "verified"` may validate in production.

## Known gaps

- Workbook texts are unaccented ASCII, except category and enum labels, the questionnaire and the risk columns, written for display: proofread the rest before UI use.
- BSH FD date decoding (year = first two digits + 1920) is documented only up to FD 9912 (December 2019); the later format is unconfirmed.
- Electrolux PNC length is unconfirmed, and several brand groups are still `to_document`: they fall back on the category's generic plate location.
- Regulations were checked in September 2026. Review `legal_obligations.json` at least yearly.
